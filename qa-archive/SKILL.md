# QA 归档

AI 负责内容选择、语义查重和分类；[scripts\archive.py](scripts/archive.py) 负责文件写入与索引生成。条目 HTML 是唯一内容来源，索引可随时重建。

## 入口与边界

- `/qa-archive [范围]`：归档指定 Q&A；无范围时选最近一组完整问答。用户明确要求归档即表示归档意图，无需推测“是否满意”。
- `/qa-archive rebuild`：只重建索引，不收集或写入问答。
- 提及命令、要求解释或修改 skill，以及自然语言“存一下”，均不执行归档。
- 交流使用中文；归档正文保留原语言，只有用户明确要求时才翻译。页面固定导航文字使用中文。
- 仅提取可见会话中的用户问题和面向用户的答案；排除内部指令、隐藏推理、工具凭据。疑似密钥或个人敏感信息先脱敏并确认。

## 1. 确定范围与位置

默认根目录 `D:\qa-arc`。检查目录、已有分类及根目录 `index.html`：

- 用户本次已指定或确认的路径直接沿用；否则将默认路径纳入本次确认。
- 目录不存在时，确认新建或改用其他路径。
- 已有 `index.html` 不含 `<!-- qa-archive:v1 -->` 时，停止写入，要求换目录或由用户先处理冲突文件。不能将其直接覆盖为知识库。
- 问答范围明确时直接提取；存在多个合理解释时列出简短候选，请用户选择。上下文缺失时请用户粘贴，不凭空重建。

**完成条件：**已确定问答候选与目标位置；尚需确认的事项集中到第 3 步一次询问。`rebuild` 只确认位置后直接进入第 4 步。

## 2. 整理、查重与分类

保留原问题的条件和答案的代码、表格、结论、限制及必要引用；去掉寒暄和重复，不自行扩写技术结论。

已有知识库先运行 `scan`（命令及 JSON 契约见 [references\operations.md](references/operations.md)），从标题、关键词和正文查找候选，再读取候选 HTML。关键词仅用于召回，不代表相同问题。

| 判断 | 动作 |
|---|---|
| 同一问题，已有内容已完整覆盖 | 跳过，不重复追加 |
| 同一问题、相同适用条件，有新内容 | `supplement`：追加补充 |
| 同一问题，新答案推翻旧结论 | `correction`：明确失效范围与更正依据，保留旧文 |
| 同主题但问题或适用条件不同 | `create`：独立条目，必要时在正文加入相对链接 |
| 多个候选或语义无法确定 | 请用户决定新建或合并到哪一条 |

更正必须已有会话依据；存在未经确认的冲突时先询问，不自行裁定。多条归档时也要进行本批次内查重；前一条落盘后重新扫描，避免使用过期的合并目标摘要。

优先复用已有分类，深度 1～2 层；新分类先确认。顶层分类超过 10 个时可以建议整理，但本次不自动迁移旧条目。

**完成条件：**每条候选都有动作、分类或目标文件及理由；更新操作记录 `scan` 返回的 `sha256`。

## 3. 合并确认

使用交互提问工具，将尚未确定的路径、新分类、范围和合并歧义放在一次确认中。已经明确指定的事项不重复问；全部确定则无需额外确认。取消时停止，未回答的必要决策不能视为同意。

**完成条件：**所有将要创建目录或改变已有内容的歧义均已解决。

## 4. 用脚本写入并重建

首次执行或处理写入/恢复分支时，读取 [references\operations.md](references/operations.md)。脚本仅依赖 Python 3.10+ 标准库，无需安装包。

1. 为每条非跳过的 Q&A 准备一份 UTF-8 JSON 输入，放在当前会话临时目录；按契约选择 `create`、`supplement` 或 `correction`。
2. 顺序运行 `write`。脚本按 [entry-template.html](entry-template.html) 创建条目，或局部更新旧条目；每次成功写入后按 [index-template.html](index-template.html) 整体重建索引。
3. 仅重建时运行 `rebuild`。只收录带条目标记的 HTML，保留用户对正文的手工编辑。
4. 读取命令结果；失败按参考文档恢复，不能把“条目已写入、索引失败”报告为全部成功。清理本次生成的临时输入文件。

**完成条件：**每条动作都有明确结果，所有成功写入均已进入可解析的索引；若未完成则明确列出失败环节和已保存路径。

## 5. 汇报

简短列出新增、补充、更正或跳过的条目及路径，给出根目录 `index.html` 的打开位置。没有变更的内容不算作新增；不要自动提交或上传知识库。
