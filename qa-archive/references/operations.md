# 脚本操作契约

以下 PowerShell 命令中的 `<skill目录>` 替换为本 skill 的绝对路径，`<会话目录>` 替换为当前会话临时文件目录。文件系统路径使用反斜杠；HTML URL 和 JSON 中的分类、条目相对路径使用 `/`。

```powershell
python "<skill目录>\scripts\archive.py" scan --root "D:\qa-arc"
python "<skill目录>\scripts\archive.py" write --root "D:\qa-arc" --input "<会话目录>\qa-input.json"
python "<skill目录>\scripts\archive.py" rebuild --root "D:\qa-arc"
```

`scan` 只读，输出带条目标记的条目元数据、正文纯文本、相对文件路径 `file` 和文件摘要 `sha256`。目录不存在时先完成新建确认；脚本的 `write`、`rebuild` 可创建已确认的根目录。无条目标记的其他 HTML 不参与查重与索引。

## 新建输入

```json
{
  "action": "create",
  "title": "如何处理 rebase 冲突",
  "category": "工作/技术",
  "keywords": ["git", "rebase", "冲突"],
  "lang": "zh",
  "question_html": "<p>执行 rebase 时出现冲突，应如何处理？</p>",
  "answer_html": "<p>原答案正文。</p><pre><code>git rebase --continue</code></pre>"
}
```

日期由本机当天日期生成，条目获得稳定 UUID；文件名为日期加清理后的短标题，重名自动加数字后缀。分类必须为 1～2 个合法 Windows 目录名；路径穿越、符号链接越界及保留设备名会被拒绝。

关键词建议 3～6 个，追加时去重合并，不为了凑数量编造。`lang` 按正文设置，默认 `zh`；内容本身不会被脚本翻译。

## 更新输入

```json
{
  "action": "supplement",
  "target": "工作/技术/2026-09-15-如何处理-rebase-冲突.html",
  "expected_sha256": "从最近一次 scan 复制的 sha256",
  "keywords": ["abort"],
  "content_html": "<p>补充正文，可保留本次问题以说明上下文。</p>"
}
```

更正使用 `action: "correction"`，另加必填字符串 `correction_note`：具体说明哪一条旧结论失效、为什么以及适用条件。脚本在页面顶部放置指向本次更正的提醒，在文末追加更正正文，不删除旧内容。

更新只替换关键词、修改日期等指定元数据，并插入新内容，原正文和手工排版保持原样。文件摘要发生变化时拒绝更新：重新读取、重新判断，不能仅复制新摘要强行重试。相同更新内容在当前条目中已有操作指纹时，返回 `skipped` 并重建索引；语义相同但表达不同的去重仍由 AI 负责。

兼容原 `entry-template.html` 生成的旧条目：从原 `dl.meta` 中读取日期、分类和关键词；旧条目无修改日期时沿用创建日期，无 ID 时按相对路径生成临时稳定 ID，首次更新将其持久化。格式缺失或不明确的标记条目会报出路径，不能静默漏掉；先确认修复该文件，再重建。

## HTML 与元数据

正文只接受受限的静态 HTML：段落、标题 h3/h4、列表、表格、引用、代码、强调、链接、折叠块。标签与属性白名单由脚本定义；不接受脚本、事件属性、内嵌样式、图片或 iframe。

- 普通文字与代码中的 `<`、`>`、`&` 必须先按 HTML 文本编码，例如 `<code>&lt;script&gt;</code>`。不要将整个正文片段转义成纯文本。
- 标题、关键词、分类和更正说明传原始文本，脚本负责 HTML 转义。
- 链接仅允许 HTTP(S)、mailto 和相对 URL；含特殊字符的本地文件链接按 URL 路径分段编码。
- 索引 JSON 使用 JSON 序列化后额外转义 `<`、`>`、`&`，避免正文中的 `</script>` 提前结束脚本。

`data-qa` 标识标题、创建日期、修改日期、分类、关键词、问题及答案；`qa-id` 元标签保存身份。展示字段就是索引提取来源，不维护第二份正文。补充和更正使用 `data-qa-operation` 指纹，保证完全相同的更新可重复执行。

## 文件保护与恢复

- 已有根索引必须带 `qa-archive:v1` 注释标记；不接管无标记的同名文件。
- 写入时创建根目录 `.qa-archive.lock` 排斥并发写入；锁存在则停止。异常退出留下锁时，确认记录的 PID 已结束且没有其他归档任务后，才允许删除这个确切的锁文件再重试。
- 内容先写入同目录临时文件，再发布；已有条目和索引原子替换，新条目发布时不覆盖重名文件。
- 条目与索引不是跨文件事务：如果条目已保存而索引失败，错误会包含保存路径。修复原因后运行 `rebuild`，不要重新新建同一问答。
- 批次顺序执行，每条立即落盘并重建；某条失败先停止，报告此前成功项及当前失败，不回滚用户内容。
- 脚本不会自动备份正文、删除条目、合并分类或上传文件。重要知识库的独立备份由用户管理。

## 样式生效范围

两个模板使用统一配色、响应式布局和系统深色模式，无外部字体、样式或脚本依赖；详情页同时提供打印样式。索引提供问答/分类统计及清除筛选，保留全文多词同时匹配。

更新模板后，`rebuild` 会刷新索引页外观；新建条目使用新版详情模板。补充、更正仍保留旧条目的原样式与手工编辑，不自动套用新模板。用户要求批量翻新已有详情页时，先单独确认迁移范围与备份方式，不将重建索引当作详情迁移。
